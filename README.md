Гибридный компрессор, объединяющий **LSTM**, статистическое моделирование контекста и **арифметическое кодирование**. Алгоритм работает на уровне байтов и обучается непосредственно во время обработки файла.

Проект реализован на Python с использованием PyTorch и NumPy. Основной сценарий запуска — сжатие тестового файла, его распаковка и автоматическая проверка точности восстановления.

## Как это работает

1. Файл читается как последовательность байтов. Уникальные значения байтов сопоставляются индексам словаря.
2. **LSTM** оценивает вероятности следующего символа, используя предыдущие символы и скрытое состояние. Веса сети обновляются во время сжатия.
3. **Контекстная модель** собирает статистику переходов между символами. Она учитывает до **5 предшествующих байтов** и использует сглаживание с опорой на более короткие контексты.
4. Прогнозы двух моделей смешиваются с фиксированным весом:

   $$P_{mix}(x) = (1-\lambda)P_{LSTM}(x) + \lambda P_{context}(x), \qquad \lambda = 0.5.$$

5. По объединённым вероятностям строятся частоты для арифметического кодера, который записывает сжатый поток.
6. При декодировании обе модели повторяют те же шаги и обновления. После восстановления файла программа сравнивает его MD5 с исходным.

Статистика контекстов общая для обрабатываемых потоков, но история символов ведётся отдельно для каждого потока. Прогноз формируется **до** чтения очередного символа, а статистика обновляется **после** него.

Результат эксперимента сохранён в [`results_reference.json`](results_reference.json). Время зависит от процессора и программного окружения; это **не** гарантированное время для любого компьютера.

## Структура репозитория

```text
coding_theory/
├── main.py                  # Сжатие, распаковка, LSTM и проверка результата
├── shared_context.py        # Статистическая контекстная модель
├── ArithmeticCoder.py       # Арифметический кодер и декодер
├── requirements.txt         # Зависимости
├── results_reference.json   # Результат контрольного эксперимента
├── .gitignore
└── data/
    └── enwik5              # Добавляется пользователем; в Git-репозитории отсутствует
```

После выполнения появятся `results.json`, `data/enwik5_compressed.dat` и `data/enwik5_decompressed.dat`.

## Установка

Рекомендуется Python **3.10+** и виртуальное окружение.

```bash
git clone https://github.com/Irbis174/coding_theory.git
cd coding_theory
python -m venv .venv
```

Активируйте окружение:

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Используются `torch>=2.5` и `numpy>=1.26`. Код принудительно выполняет вычисления на **CPU**.

### Подготовка данных

**Важно:** файл `data/enwik5` не включён в опубликованный репозиторий. Перед запуском создайте каталог `data` и поместите в него тестовый файл с точным именем `enwik5` (без расширения):

```text
coding_theory/data/enwik5
```

Для воспроизведения указанного результата нужен тот же файл размером **100 811 байт**. Другие файлы могут дать другие коэффициенты сжатия.

## Запуск

Все параметры заранее заданы в `main.py`, поэтому дополнительных аргументов не требуется:

```bash
python main.py
```

Программа последовательно:

1. сжимает `data/enwik5` в `data/enwik5_compressed.dat`;
2. распаковывает архив в `data/enwik5_decompressed.dat`;
3. проверяет совпадение MD5 исходного и восстановленного файлов;
4. выводит коэффициент сжатия, длительность выполнения и информацию об использовании GPU;
5. записывает итоговые метрики в `results.json`.

При несовпадении MD5 выполнение завершается ошибкой, а в `results.json` сохраняется `success: false` и описание ошибки.

Параметры зафиксированы в словаре `CONFIG` в начале `main.py`:

```python
CONFIG = {

    "rnn_units": 768,
    "embedding_size": 150,
    "start_learning_rate": 0.005,
    "end_learning_rate": 0.0001,
```

Внешний `params.json` и аргументы командной строки не используются. Для воспроизведения эталонного эксперимента оставьте параметры без изменений.

## Особенности и ограничения

- Это экспериментальный **lossless-компрессор**, а не универсальный архиватор с полноценным интерфейсом командной строки.
- `main.py` выполняет **сжатие и распаковку за один запуск**. Путь к входному файлу задан в коде.
- Предобученные веса не сохраняются: нейросеть обучается синхронно при кодировании и декодировании.
- Для корректной распаковки нужны одинаковые параметры, версия алгоритма и совместимые численные вычисления. Архив не является самодостаточным форматом для произвольных реализаций декодера.
- Для повторяемости используется фиксированный seed и CPU; численные различия между программными окружениями могут влиять на синхронизацию.
- Коэффициент сжатия зависит от содержимого файла. Результат для `enwik5` не гарантирует такую же эффективность на любых данных.
